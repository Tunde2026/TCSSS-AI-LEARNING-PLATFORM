## 3. Architecture Rules (non-negotiable)

These rules were established after painful bugs. Do not break them.

### Rule 1 — The LLM decides; the application executes.
The AI returns structured intents (tool calls). The backend validates
and executes them. The AI never directly performs privileged operations.

### Rule 2 — Migrations are append-only.
Never edit a merged migration. Always create a new file: `023_*.sql`,
`024_*.sql`, etc. The next number is 034.

### Rule 3 — Every module exposes only through its `index.js`.
Routers, services, and helpers are re-exported from `index.js`. Other
modules import from the folder root, not from individual files.

### Rule 4 — `routes.js` exports the Express router directly.
- `routes.js` files do: `module.exports = router;`
- Other files do: `module.exports = { fn1, fn2 };`
- NEVER mix these. This caused a critical bug before.

### Rule 5 — All AI requests go through the AI Gateway.
Never call providers directly from routes. Always `require('../ai').gateway.chat()`
or the higher-level `runWithTools()` in `ai/tool-executor.js`.

### Rule 6 — Never trust the browser for roles, scores, exam results.
Server-side scoring only. The client never sends the truth.

### Rule 7 — Never expose secrets.
No secrets in frontend code, HTML, logs, commits, screenshots, or chat.
The `.env` file is never committed. `.env.example` contains only names.

### Rule 8 — Route ordering in Express.
Static-string paths (`/folders`, `/unread`) MUST come BEFORE parameterized
paths (`/:id`), or Express treats `folders` as an `:id` and 404s.

### Rule 9 — Protected accounts cannot be demoted, suspended, or deleted.
Enforced both at the API layer and via the `is_protected` database flag.

## 11. AI Layer

### Gateway (`ai/gateway.js`)
The gateway is the single entry point for all LLM requests.

**Fallback chain (in order):**
1. Groq (up to 2 keys)
2. Cerebras
3. Google (Gemini)
4. NVIDIA NIM
5. OpenRouter
6. Ollama — tries each of these models in sequence:
   - `qwen2.5:3b` (fast)
   - `llama3.1:8b` (quality)
   - `deepseek-r1:7b` (math/science)
   - `qwen2.5:7b` (all-rounder)

**Key behaviors:**
- Each key has its own health state (failures, cooldown)
- 429 → cooldown that key, try next
- 401/403 → disable that key permanently, try next
- 404 → try next provider (model retired)
- 5xx / timeout → cooldown, try next
- 400 / 422 → STOP (our request is malformed)
- Message history is trimmed: max 16 messages, max 5500 estimated tokens
  (Groq free tier caps at 8000 TPM)

### Tool-calling architecture
Two paths — native first, regex fallback second:

**Path A — Native tool-calling (preferred):**
1. Frontend sends user message to `/api/ai/chat`
2. Backend calls `runWithTools()` in `ai/tool-executor.js`
3. That sends `tools: [...TOOL_SCHEMAS]` to the gateway
4. AI returns `tool_calls` in the response
5. `ai/tool-dispatch.js` maps each call to the right service
6. The result is sent back to the AI as a `role: tool` message
7. AI produces a natural-language summary
8. Tool objects and reply are saved and returned to frontend

**Path B — Regex fallback (only if native didn't fire):**
1. `runToolDetection()` in `ai/routes.js` scans user text for intent
2. Regex patterns detect "quiz me on X", "make flashcards on Y", etc.
3. The matching service runs directly
4. The tool object is added to the response

**Available tools (13 total):**
- `create_quiz` — multi-choice quiz
- `create_flashcards` — flip-card deck
- `create_theory` — fill-in-the-gap theory
- `create_practice` — practice questions
- `create_study_plan` — multi-day study plan
- `create_exam` — timed exam
- `create_visualization` — Mermaid diagram
- `create_sketch` — formula/equation formatter + solver
- `web_search` — Tavily search
- `search_images` — Pexels search
- `generate_image` — Pollinations
- `save_note` — save to notes
- `get_mistakes` — show mistake bank

### Vision layer (`ai/vision.js`)
When a student attaches an image:
1. Detect the image in `chat_attachments` (mime starts with `image/`)
2. Read file bytes from disk (`storage_path`)
3. Send base64 to OpenAI `gpt-4o-mini` with the user's prompt
4. **Fallback:** if OpenAI fails (no credits, error), retry with Ollama `llava:7b`
5. If both fail, return an honest "I could not read that image" message

### Voice layer (`voice/`)
Provider chain:
1. OpenAI Whisper (if `VOICE_PROVIDER=openai`)
2. Deepgram Nova-2 (if `VOICE_PROVIDER=deepgram`)
3. Local `whisper.exe` (local dev only)

Endpoint: `POST /api/voice/transcribe` with `multer` handling the upload.
Returns `{ text, provider }`.

## 14. Development Conventions

### File organization
- Backend modules live under `backend/src/<module>/`
- Every module has `index.js` (exports), `routes.js` (Express router),
  `service.js` (business logic)
- DB queries live in `backend/src/db/queries/<domain>.js`
- Every query module is re-exported from `backend/src/db/index.js`

### Adding a new feature
1. Write migration `0NN_*.sql` (append-only)
2. Add DB queries file in `db/queries/`
3. Export from `db/index.js`
4. Add service file with business logic
5. Add routes with auth guards + audit logging
6. Mount router in `server.js` (respect route ordering rule)
7. Add frontend page if user-facing
8. Add nav item in `shell.js` if it needs one

```js
await audit.log({

```
Audit log never fails the caller — silent catch on error.

- Design tokens via CSS variables from `shell.css`

- Mobile-first: base styles, then `@media (min-width: 640px)`
